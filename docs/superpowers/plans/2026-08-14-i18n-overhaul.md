# i18n Overhaul Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace three disconnected, partially-broken i18n mechanisms with one consistent system built on `astro:i18n` (`routing: "manual"`), where every page — including the homepage and legal pages — resolves language from a real prefixed URL, and language reaches every Vue island via props instead of a nanostore that nothing reliably sets.

**Architecture:** `astro.config.mjs` declares `i18n: { locales: ["de","en"], defaultLocale: "de", routing: "manual" }`. A new `src/middleware.ts` redirects `/` to `/de` and 404s unconfigured-locale-shaped paths. The homepage and legal pages move under `src/pages/[lang]/...`, matching the pattern already used by `[...about].astro`. `getLangFromUrl` is replaced by Astro's built-in `Astro.currentLocale`. The dead `currentLanguage`/`translationRoutes` nanostores and the orphaned `@nanostores/i18n` setup are deleted; every Vue island that needs the current language receives it as a `lang` prop threaded down from the Astro page that already knows it.

**Tech Stack:** Astro 7.2 (`astro:i18n`, `astro:middleware`), Vue 3 islands, WPGraphQL via `wpQuery`, Vitest + Vue Test Utils, Playwright (driven here via the `playwright-test-planner` / `playwright-test-generator` / `playwright-test-healer` MCP agents).

**Spec:** `docs/superpowers/specs/2026-08-14-i18n-overhaul-design.md`

## Global Constraints

- Locales are exactly `de` (default) and `en` — no other languages.
- `routing: "manual"` — never switch to Astro's automatic locale-folder routing (rejected in the spec: incompatible with WPGraphQL-driven dynamic routes).
- String translation (`useTranslations`, `localeStrings`, `de-DE.json`/`en-US.json`) is unchanged — only routing/URL and state-propagation concerns are touched.
- Language reaches Vue islands via props, never via a nanostore (per the approved design decision).
- `pnpm run typechecking` (`astro check && vue-tsc --noEmit`) and `pnpm run test:unit` must stay green after every task.
- Follow existing code style: no new abstractions beyond what a task needs, reuse `PageFieldFragment`/`wpQuery`/`useFragment` patterns already established in `[...about].astro`.

- [ ] **Step 4: Create `src/middleware.ts`**

```ts
import { defineMiddleware } from "astro:middleware";
import { notFound, redirectToDefaultLocale, requestHasLocale } from "astro:i18n";

// Only paths that look like a locale attempt (exactly two lowercase letters
// as the first segment) are treated as "must resolve to a configured
// locale or 404". Every other path (/api/*, /404, /sitemap-index.xml,
// /robots.txt, static assets) is left alone — none of them are 2 lowercase
// letters, so this can't shadow them.
export const isLocaleShapedPath = (pathname: string): boolean => /^\/[a-z]{2}(\/|$)/.test(pathname);

export const onRequest = defineMiddleware((context, next) => {
  const { pathname } = context.url;

  if (pathname === "/") {
    return redirectToDefaultLocale(context, 302);
  }

  if (isLocaleShapedPath(pathname) && !requestHasLocale(context)) {
    return notFound();
  }

  return next();
});
```
